# RFC-0005: Quantitative Perceptual Measurement Model

- Status: Draft
- RFC: 0005
- Target: Future OpenSmell version
- Category: Representation Scheme
- Authors: OpenSmell contributors

## Summary

This RFC proposes a representation model for quantitative perceptual
measurements in OpenSmell.

The purpose of the representation is to describe measured or derived
perceptual properties of an odor using explicit numerical values and
measurement scales.

Examples include:

- perceived intensity;
- pleasantness;
- familiarity;
- quantitative descriptor applicability;
- other numerical perceptual dimensions.

The representation is intended to remain independent from any particular
psychophysical experiment, dataset, machine-learning model, or physical
olfactory device.

This proposal is motivated by interoperability requirements observed while
analyzing the Keller/Vosshall psychophysical olfaction dataset.

It does not modify OpenSmell 0.1.

---

## Motivation

OpenSmell currently distinguishes several broad representation categories,
including semantic and perceptual representations.

RFC-0004 addresses semantic annotation states such as:

```text
floral -> present
woody  -> absent
spice  -> unknown
```

This model is appropriate for categorical information.

However, olfactory perception is frequently represented quantitatively.

For example:

```text
intensity    = 61 / 100
pleasantness = 45 / 100
familiarity  = 73 / 100
flower       = 82 / 100
```

Reducing these values to categorical annotations such as:

```text
flower -> present
```

would discard information.

Similarly, interpreting a numerical perceptual rating as a confidence score
would assign semantics that may not exist in the source data.

A separate perceptual measurement representation is therefore required.

---

## Observed interoperability problem

Analysis of the Keller/Vosshall psychophysical dataset exposed several kinds
of perceptual information that cannot be represented losslessly by the
existing semantic schemes.

The analyzed dataset contains:

```text
55,000 experimental observations
55 subjects
480 unique PubChem CIDs
4 source dilution levels
```

Each subject contributed 1,000 observations.

Subjects first indicated whether they detected the stimulus.

Observed detection responses were:

```text
I smell something:          41,289
I can't smell anything:     13,711
```

When a stimulus was detected, three global perceptual ratings were available:

```text
intensity
pleasantness
familiarity
```

These values span a numerical scale from 0 to 100.

The dataset also contains twenty quantitative descriptor dimensions:

```text
EDIBLE
BAKERY
SWEET
FRUIT
FISH
GARLIC
SPICES
COLD
SOUR
BURNT
ACID
WARM
MUSKY
SWEATY
AMMONIA/URINOUS
DECAYED
WOOD
GRASS
FLOWER
CHEMICAL
```

Observed populated descriptor values range from 1 to 99.

The experimental methodology indicates that descriptor sliders started at
zero and did not necessarily need to be moved.

Therefore an unpopulated source cell cannot safely be assigned OpenSmell
semantics without considering the experimental protocol.

This demonstrates that perceptual values require explicit measurement
semantics and context.

---

## Goals

The proposed scheme SHOULD:

1. represent quantitative perceptual measurements;
2. preserve numerical values without reducing them to categories;
3. explicitly describe the scale used by a measurement;
4. remain independent from a specific dataset;
5. remain independent from a specific experimental protocol;
6. support both global perceptual dimensions and descriptor ratings;
7. allow measurement context to be preserved;
8. distinguish a numerical zero from a measurement that was not performed;
9. support future human, aggregate, and computational perceptual data;
10. coexist with semantic representations.

---

## Non-goals

This RFC does not attempt to:

- define a universal perceptual odor space;
- define a universal descriptor vocabulary;
- standardize psychophysical experiments;
- define subject databases;
- define clinical study records;
- define chemical identity;
- predict perception from molecular structure;
- define physical scent reproduction;
- define device control commands;
- define statistical aggregation methods;
- define confidence semantics;
- determine whether a perceptual measurement is scientifically correct.

## Proposed scheme

Provisional scheme identifier:

```text
org.opensmell.perceptual.measurements
```

Provisional version:

```text
0.1
```

Representation type:

```text
perceptual
```

Example:

```json
{
  "type": "perceptual",
  "scheme": {
    "id": "org.opensmell.perceptual.measurements",
    "version": "0.1"
  },
  "data": {
    "measurements": [
      {
        "property": "intensity",
        "value": 61,
        "scale": {
          "min": 0,
          "max": 100
        }
      },
      {
        "property": "pleasantness",
        "value": 45,
        "scale": {
          "min": 0,
          "max": 100
        }
      }
    ]
  }
}
```

---

## Measurement object

Each measurement contains at minimum:

```text
property
value
scale
```

A conceptual measurement therefore has the form:

```text
property + numerical value + interpretation scale
```

Example:

```json
{
  "property": "intensity",
  "value": 61,
  "scale": {
    "min": 0,
    "max": 100
  }
}
```

---

## `property`

`property` identifies the perceptual dimension being measured.

It MUST be a non-empty string.

Examples include:

```text
intensity
pleasantness
familiarity
flower
sweet
chemical
```

OpenSmell Core MUST NOT assign universal semantics to arbitrary property
names.

The interpretation of a property may depend on:

- the representation scheme;
- an external vocabulary;
- source documentation;
- experimental provenance.

A future extension MAY introduce explicit vocabulary identifiers.

---

## `value`

`value` contains the observed, aggregated, or derived numerical measurement.

It MUST be numeric.

Example:

```json
{
  "property": "intensity",
  "value": 61,
  "scale": {
    "min": 0,
    "max": 100
  }
}
```

A value MUST NOT be interpreted independently from its scale and measurement
context.

For example:

```text
61
```

does not inherently mean:

```text
61 percent
61 percent confidence
61 percent intensity
```

Its meaning is defined by the measurement property, scale, and source
semantics.

---

## Scale

A numerical perceptual measurement requires information about the scale on
which it was expressed.

The initial proposal defines:

```text
min
max
```

Example:

```json
{
  "min": 0,
  "max": 100
}
```

`min` and `max` MUST be numeric.

`min` MUST be less than `max`.

The measurement value SHOULD fall within the declared scale.

A future version MAY require additional scale semantics such as:

```text
anchors
units
scale type
normalization method
```

These are deliberately excluded from the initial proposal until additional
real-world requirements are evaluated.

---

## Zero versus missing measurement

A numerical value of zero is a measurement.

The absence of a measurement is not a numerical value.

Therefore:

```json
{
  "property": "flower",
  "value": 0,
  "scale": {
    "min": 0,
    "max": 100
  }
}
```

is semantically different from the complete absence of a `flower`
measurement.

Implementations MUST NOT automatically convert missing measurements to zero
unless the semantics of the source protocol explicitly justify that
conversion.

Similarly, implementations MUST NOT convert a zero measurement into an
unknown or missing state.

This distinction is essential for lossless conversion of experimental data.

---

## Detection versus perception

Stimulus detection is not equivalent to a perceptual rating.

For example:

```text
subject did not detect stimulus
```

does not necessarily mean:

```text
intensity = 0
pleasantness = 0
flower = 0
```

The measurement may simply not have been performed.

The Keller/Vosshall dataset demonstrates this distinction: observations in
which subjects reported that they could not smell the stimulus contain no
subsequent perceptual ratings.

OpenSmell implementations MUST therefore avoid inferring numerical
perceptual measurements from a detection result.

Detection may eventually require its own contextual or observational model.

---

## Quantitative descriptors

Semantic descriptors and quantitative perceptual descriptors represent
different information.

For example:

```text
semantic:
flower -> present
```

and:

```text
perceptual:
flower -> 73 / 100
```

are not equivalent.

The first represents a categorical assertion.

The second represents a numerical perceptual rating.

An application MAY derive a categorical representation from a quantitative
measurement if it uses an explicitly defined transformation.

Such a transformation SHOULD be recorded through provenance when possible.

OpenSmell MUST NOT define an implicit threshold such as:

```text
value > 0 -> present
```

because that threshold may not be valid across datasets or protocols.

---

## Measurement context

Perceptual measurements depend on context.

Potential contextual variables include:

```text
stimulus concentration
stimulus dilution
presentation method
subject or observer
population
experimental protocol
environmental conditions
aggregation method
prediction model
```

For example, the same molecule may produce different perceived intensity at
different concentrations.

Likewise, two human observers may provide different ratings for the same
stimulus.

Therefore perceptual measurements MUST NOT be treated as unconditional
intrinsic properties of a molecule.

---

## Stimulus context

The Keller/Vosshall dataset contains explicit odor dilution information.

Observed source dilution levels include:

```text
1/10
1/1,000
1/100,000
1/10,000,000
```

This demonstrates that stimulus context may be necessary to interpret
perceptual measurements.

However, this RFC does not yet define a normative concentration or dilution
model.

Representing concentrations correctly may require support for:

- ratios;
- mass concentration;
- volume concentration;
- molar concentration;
- carrier medium;
- preparation method.

A separate future model MAY be preferable to embedding experimental
concentration semantics directly into this representation scheme.

---

## Observer context

Human perceptual measurements may originate from:

```text
one individual
multiple individuals
a population aggregate
```

Computational perceptual measurements may originate from:

```text
a machine-learning model
a statistical model
another transformation
```

The measurement representation SHOULD eventually allow these cases to be
distinguished.

However, this RFC deliberately does not define a normative `subject_id`
field.

OpenSmell is an interoperability framework for olfactory information, not a
subject-management or clinical-study format.

A future observation-context mechanism MAY reference an external subject,
population, model, or experiment without embedding their complete records.

---

## Individual versus aggregate measurements

A perceptual value may represent an individual observation:

```text
subject A:
intensity = 61
```

or an aggregate:

```text
population mean:
intensity = 54.2
```

These values are not semantically equivalent.

An aggregate may also require additional information such as:

```text
aggregation method
sample size
dispersion
confidence interval
```

The initial measurement model does not standardize these statistical fields.

Implementations SHOULD preserve this information through extensions or
provenance when required.

Future RFCs MAY define a normative aggregate measurement model.

---

## Human versus computational measurements

OpenSmell SHOULD NOT assume that perceptual measurements originate from
humans.

For example, a model may predict:

```text
pleasantness = 62
```

on a documented perceptual scale.

This remains perceptual information even though it was computationally
derived.

The distinction between:

```text
observed
aggregated
predicted
transformed
```

belongs to provenance and measurement context rather than the numerical
value itself.

---

## Provenance

Perceptual measurements require strong provenance.

For example:

```text
intensity = 61
```

is difficult to interpret without knowing where the value originated.

Until provenance becomes normative, implementations MAY use the extension
mechanism explored by RFC-0003.

Example:

```json
{
  "type": "perceptual",
  "scheme": {
    "id": "org.opensmell.perceptual.measurements",
    "version": "0.1"
  },
  "data": {
    "measurements": [
      {
        "property": "intensity",
        "value": 61,
        "scale": {
          "min": 0,
          "max": 100
        }
      }
    ]
  },
  "provenance": {
    "source": "Keller/Vosshall"
  }
}
```

Future provenance requirements may include:

```text
dataset version
experimental protocol
measurement method
model identifier
transformation chain
timestamp
```

---

## Relationship to RFC-0004

RFC-0004 and RFC-0005 address different interoperability requirements.

RFC-0004:

```text
semantic.annotations

floral -> present
woody  -> absent
spice  -> unknown
```

RFC-0005:

```text
perceptual.measurements

flower       -> 73 / 100
intensity    -> 61 / 100
pleasantness -> 45 / 100
```

Conceptually:

```text
OpenSmell
|
+-- semantic
|   |
|   +-- descriptors
|   |
|   +-- annotations
|       |
|       +-- present
|       +-- absent
|       +-- unknown
|
+-- perceptual
    |
    +-- measurements
        |
        +-- numerical value
        +-- explicit scale
        +-- measurement context
```

Neither representation should replace the other.

---

## Relationship to chemical representations

A perceptual representation describes perception, not molecular identity.

Therefore:

```text
chemical.smiles
```

and:

```text
perceptual.measurements
```

may coexist as representations of the same conceptual odor.

For example:

```text
Odor
|
+-- chemical representation
|   +-- SMILES
|
+-- perceptual representation
    +-- intensity
    +-- pleasantness
    +-- descriptors
```

OpenSmell MUST NOT assume that a chemical structure uniquely determines a
single perceptual measurement.

---

## Dataset-specific vocabularies

The twenty Keller/Vosshall descriptors are not declared universal OpenSmell
perceptual dimensions by this RFC.

Another dataset may use:

```text
citrus
earthy
mint
leather
metallic
```

or an entirely different perceptual space.

The scheme therefore transports property names without declaring them
universal.

A future vocabulary mechanism MAY provide identifiers such as:

```json
{
  "vocabulary": {
    "id": "org.example.perceptual-vocabulary",
    "version": "1.0"
  }
}
```

This is deliberately deferred.

---

## Validation considerations

A future validator for this scheme would likely verify that:

- `measurements` is an array;
- the array is not empty;
- every measurement contains a non-empty `property`;
- every measurement contains a numeric `value`;
- every measurement contains a `scale`;
- every scale contains numeric `min` and `max`;
- `min` is less than `max`;
- the measurement value lies within the declared scale.

A validator MUST NOT attempt to determine whether a perceptual measurement is
scientifically correct.

A validator MUST NOT assume that different measurements using the same
numerical range are directly comparable.

---

## Backward compatibility

This proposal does not modify the OpenSmell 0.1 document structure.

The representation uses the existing generic representation model:

```text
type
scheme
data
```

An OpenSmell 0.1 implementation that does not understand:

```text
org.opensmell.perceptual.measurements
```

should still be able to preserve the representation as an unknown scheme.

This allows experimental implementations to evaluate the model without
changing OpenSmell Core.

## Experimental validation plan

The Keller/Vosshall dataset was selected as the first experimental validation
source for this proposal.

The validation pipeline was designed as:

```text
Keller/Vosshall XLSX
        |
        v
OpenSmell experimental adapter
        |
        v
perceptual.measurements representation
        |
        v
OpenSmell serializer
        |
        v
.osmell document
        |
        v
OpenSmell parser
        |
        v
recovered perceptual measurements
        |
        v
comparison with source values
```

The validation was designed to verify at minimum:

```text
property identity
numerical value
scale boundaries
measurement presence
measurement absence
```

The experiment also preserved the distinction between:

```text
numerical zero
missing measurement
observation without perceptual measurements
```

No implicit zero values were generated from missing source cells.

## Experimental validation

The proposed quantitative perceptual measurement model was evaluated against
the Keller/Vosshall psychophysical olfaction dataset using the experimental
OpenSmell Keller/Vosshall adapter.

The validation dataset contained:

```text
Experimental observations:      55,000
Observations with measurements: 41,289
Observations without measures:  13,711
Explicit measurements:         263,683
```

The validation intentionally preserved only perceptual measurements explicitly
stored in the source workbook.

Missing descriptor cells were not automatically converted to numerical zero,
even where the experimental protocol may provide enough context to interpret
an untouched descriptor slider as zero.

This separation allows raw source preservation to remain distinct from
protocol-aware normalization.

For every source observation containing explicit perceptual measurements, the
validation pipeline performed:

```text
Keller/Vosshall XLSX
        |
        v
experimental adapter
        |
        v
perceptual.measurements representation
        |
        v
OpenSmell serialization
        |
        v
.osmell document
        |
        v
OpenSmell parser
        |
        v
recovered perceptual measurements
        |
        v
comparison with source values
```

Observations containing no explicit perceptual measurements were also checked
to ensure that the adapter did not invent a perceptual representation.

The result was:

```text
Observations:              55,000
With measurements:         41,289
Without measurements:      13,711
Measurements checked:     263,683
Expected measurements:    263,683
Mismatches:                     0
```

All 263,683 explicitly stored perceptual measurements survived the OpenSmell
serialization and parsing round trip without information loss.

The experiment verified:

- measurement property identity;
- numerical measurement values;
- scale boundaries;
- measurement presence;
- measurement absence;
- observations containing no perceptual measurements.

The result demonstrates that the proposed minimal
`org.opensmell.perceptual.measurements` representation can losslessly
transport the explicit quantitative perceptual measurements observed in the
tested Keller/Vosshall dataset.

It does not demonstrate that the model is sufficient for all psychophysical
experiments or perceptual datasets.

In particular, stimulus concentration, observer identity, repeated
observations, scale anchors, aggregation, uncertainty, and protocol-aware
interpretation remain open interoperability questions.

The experiment validates information preservation, not the scientific
correctness or comparability of the source measurements.

---

## Open questions

### 1. How should measurement context be represented?

It is not yet clear whether context belongs:

- inside each representation;
- inside each measurement;
- in a separate observation object;
- in another OpenSmell representation.

The answer should be driven by additional real-world datasets.

### 2. How should stimulus concentration be represented?

Simple strings such as:

```text
1/1000
```

are insufficient for a universal concentration model.

A structured stimulus model may eventually be required.

### 3. How should observers be referenced?

OpenSmell should support individual measurements without becoming a
subject-management system.

A lightweight external-reference mechanism may be sufficient.

### 4. How should aggregate measurements be represented?

Means, medians, distributions, sample sizes, and uncertainty may require a
separate statistical model.

### 5. Should scales support anchors?

A scale from 0 to 100 may have semantic endpoints such as:

```text
not pleasant -> extremely pleasant
```

Those anchors may be necessary for reliable interoperability.

### 6. Should scale type be explicit?

Possible scale types include:

```text
visual analogue
ordinal
interval
normalized
probability
model score
```

Further datasets are required before defining a normative taxonomy.

### 7. How should missing values be represented?

A missing value may mean:

```text
not measured
not applicable
not detected
unknown
source value missing
```

These meanings MUST NOT be collapsed without evidence.

### 8. Should descriptor vocabulary be explicit?

Property names such as `flower` may require a vocabulary identifier to
distinguish dataset-specific semantics.

### 9. How should repeated observations be represented?

The same odor may have multiple measurements from the same observer,
different observers, concentrations, or experimental sessions.

This may require a model above individual perceptual representations.

## Implementation plan

This RFC should initially remain experimental.

Proposed development sequence:

```text
1. Analyze Keller/Vosshall source semantics
              |
              v
2. Define minimal perceptual measurement model
              |
              v
3. Implement experimental scheme validator
              |
              v
4. Implement Keller/Vosshall adapter
              |
              v
5. Perform lossless round-trip validation
              |
              v
6. Analyze failures and contextual requirements
              |
              v
7. Evaluate a second quantitative perceptual dataset
              |
              v
8. Refine measurement/context separation
              |
              v
9. Decide whether the scheme belongs in OpenSmell 0.2
```

Steps 1 through 5 have now been experimentally completed.

The first round-trip validation produced zero mismatches across 263,683
explicit perceptual measurements.

The remaining work should focus on testing whether the model generalizes
beyond Keller/Vosshall before this representation becomes normative.

## Conclusion

Quantitative olfactory perception cannot be represented losslessly as a set
of categorical semantic annotations.

Real psychophysical data contains numerical perceptual measurements whose
meaning may depend on:

```text
property
value
scale
stimulus
observer or source
experimental context
```

The Keller/Vosshall experiment demonstrates that the proposed minimal
`property + value + scale` abstraction can preserve all 263,683 explicit
perceptual measurements tested through a complete OpenSmell serialization and
parsing round trip with zero mismatches.

It also demonstrates that observations without measurements can remain
distinct from numerical zero values.

RFC-0005 therefore provides an experimentally supported candidate model for
quantitative perceptual information while deliberately leaving complex
experimental context, statistics, observer management, concentration
modeling, and protocol-aware normalization open for further investigation.

Further validation against an independent quantitative olfactory source is
required before the model should become normative.

This preserves the central OpenSmell principle that representations should
transport olfactory information without assuming how that information was
generated or how an odor will ultimately be physically reproduced.
