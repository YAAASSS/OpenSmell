# RFC-0016: Recoverable Core source in graph projections

- Status: Draft
- Created: 2026-11-12
- Scope: Experimental import/export tooling; no change to Core 0.1

## Purpose

Let an application exchange a usable graph projection while retaining the exact
original Core document, including unknown data. Extraction means original-source
recovery, not inverse mapping of graph edits. The existing chemical/annotation
bridge remains the projection policy.

## Extension

A generic ResourceGraph may carry the top-level extension
`org.opensmell.experimental.core-import` with:

| Field | Value |
| --- | --- |
| version | `0.1` |
| projection | `core-odor-smiles-annotations-v1` |
| primary_resource_id | Projected main Molecule ID |
| annotation_ids | Projected annotation IDs |
| source.encoding | `base64` |
| source.data | Base64 encoding of the complete original UTF-8 Core file |
| source.sha256 | Lowercase SHA-256 of those original bytes |
| source.byte_count | Nonnegative integer byte length |
| source.odor_id | ID in the validated source Core document |
| limitations | Human-readable statements of projection/recovery limitations |

IDs identify projected resources, not authenticated claims. Source hashes identify
bytes; they do not authenticate the source or bind later graph edits. Consumers
must not apply graph changes when extracting the original. Snapshot metadata is
an extension: generic graph readers may preserve it without interpreting it.

## Validation and compatibility

The installed producer requires strict JSON and a valid unambiguous Core 0.1
document, then applies the existing exactly-one-supported-SMILES bridge. Unknown
fields survive in the snapshot even when the projection does not model them.
The consumer validates the graph envelope/resources, supported snapshot
version/projection/encoding, strict base64, byte count, hash, Core document and
source odor identity. It does not verify semantic equivalence of a modified graph.

The source snapshot can be large or sensitive. Applications must account for its
size and disclosure. This Draft adds no authentication, chemical verification,
inverse bridge, device capability or measured olfactory outcome.

## Executable evidence

See [the installed walkthrough](../docs/core-interchange.md) and
`tools.verify_installed_cli`: Core input → graph validation → semantic plan →
software Python/Node lifecycle, plus exact original-source recovery. Tests cover
unknown content, corruption, unsupported inputs and exclusive output creation.
