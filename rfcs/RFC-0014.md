# RFC-0014: Local simulated execution lifecycle

- Status: Draft
- Date: 2026-11-05
- Scope: executable Local Explorer experiment, non-normative

## Motivation

Device Protocol 0.1 confirms acceptance, not completion. A reproducible software
endpoint lets developers observe this distinction and test interruption without
operating physical hardware. Do not add assumed lifecycle support to existing
physical adapters or reinterpret their `ok` responses.

## First vertical slice

`python -m apps.local_demo --simulate` selects an in-process endpoint with a
separate identity, `opensmell-local-simulator-001`. Existing 0.1 hello,
capabilities and render messages are reused for the plan. An accepted render
reply adds a fresh `execution_id`. The endpoint validates the plan and owns its
monotonic deadline. No mapper or scientific data changes are required.

The following app-local JSON messages are **not Device Protocol 0.1 messages**.
They are an experimental profile named `local-simulator-lifecycle-v1`:

- `{"type":"lifecycle_capabilities"}` returns
  `{"profile":"local-simulator-lifecycle-v1","status":true,"stop":true}`.
- `{"type":"execution_status","profile":"local-simulator-lifecycle-v1","execution_id":"..."}`
  returns the same profile and ID plus `state`: `running`, `completed` or `stopped`.
- `stop` uses the same request envelope and response. A running execution becomes
  stopped; an already completed execution stays completed. Repeated Stop is
  harmless for the current terminal execution. Unknown or superseded IDs fail.

Local Explorer verifies profile, execution ID and allowed state before showing
an observation. It exposes the reply in **View command response**. Link loss or
malformed/mismatched replies produce `unknown`, never an inferred completion.
Explicit disconnect before a terminal observation likewise preserves uncertainty.
The endpoint retains its latest execution only; the application retains the last
observation. Neither claims durable logs or reconnect reconciliation.

Status polling queries the endpoint but does not start or stop an execution.
Only explicit POST actions submit plans or request Stop. Existing loopback,
Host/Origin, freshness, single-use preview, serialized operation and capability
checks remain in force. Simulator mode rejects all ports except `SIMULATED`.

## Evidence and limits

HTTP integration cases cover completion, Stop, old-ID rejection, duplicate send,
wrong-ID replies, duration refusal and disconnect/transport failure. A JavaScript
DOM-double test checks labels, Stop capability gating and ID-bearing requests.
This is one implementation in one process; it is not independent interoperability,
network resilience, physical telemetry or measured odor reproduction.

## Second implementation evidence — 2026-11-06

The [Node.js example](../examples/lifecycle_adapter/README.md) implements the
messages without importing the Python SDK and runs in a separate process.
Local Explorer selects it with `--simulate-node`; its distinct identity is
`opensmell-node-simulator-001`. The original Python endpoint is unchanged.

`python -m tools.verify_lifecycle_adapter --endpoint node` and `--endpoint python`
run common live cases and emit the actual exchanges: completion, terminal Stop,
stale Stop rejection, correlated interruption and unknown after transport loss.
This is observed local cross-language exchange between repository-maintained
implementations, not third-party or physical compatibility. The profile remains
Draft and app-local.

The executable wire example uses one JSON object per UTF-8 line. Its client
permits 65,536 bytes per line and a two-second exchange timeout, closes the
process after failure and never retries. The Node endpoint returns an error
object for invalid requests; the Python in-process endpoint raises ValueError.
Error envelope harmonization is therefore still required before standardization.
Process closure is a test of link loss, not reconnect/restart reconciliation.

## Next proof

Extend the shared reference cases to restart/reconnect and negotiated errors.
Revisit capability negotiation, request correlation, restart/reconnect semantics,
error envelopes and bounded transport timeouts before promoting this profile to
an SDK/protocol contract. No firmware compatibility is claimed by this Draft.
