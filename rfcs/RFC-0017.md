# RFC-0017: Selected-record CSV import context

- Status: Draft
- Created: 2026-11-12
- Scope: Experimental OdorNet-shaped CSV importer; no Core 0.1 changes

The [input contract](../docs/csv-import.md) requires exact column names and an
explicit one-based logical record index. A source manifest supplies nonempty
name/url/license and a dataset/synthetic kind. This is a declaration, not an
authenticated attribution or license check.

The importer uses the existing OdorNet adapter for chemical SMILES and the twelve
semantic annotation states. Blank cells stay unknown. It does not validate
chemical structure, infer missing categories or interpret extra columns.

The document extension `org.opensmell.experimental.csv-import` version 0.1
contains adapter `odornet-shaped-csv-v1`, source manifest, its canonical JSON
SHA-256 (sorted keys, compact separators, ASCII escaping), original CSV byte
SHA-256/count, one-based data_record, ordered headers, raw_record strings and
human-readable limitations. Deterministic UUIDv5 IDs are based on CSV hash,
record index and source-manifest hash in that order, separated by newlines,
using namespace `e6e81508-d0f0-431e-87ad-882b2cd5503a`.

The full original CSV is not embedded; raw_record preserves selected cell values
but not original quoting/framing. It is not a reversible CSV serialization.
Representation provenance uses the declared source, kind, license/URL, CSV hash,
record index and adapter identifier. Synthetic data must not be relabeled as
observed real data by the importer.

Unknown columns and manifest fields are retained. Only selected-record semantic
values are validated, not the full corpus. Existing Core and graph snapshot
mechanisms preserve this extension. Installed-wheel evidence runs CSV → Core →
graph → plan → Python/Node software execution and Core recovery. These tests do
not certify an upstream release, measured odor output or independent adoption.
